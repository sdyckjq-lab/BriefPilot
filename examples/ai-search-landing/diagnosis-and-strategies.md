# AI 搜索产品官网 Diagnosis and Strategies

## Raw Request

```text
帮我做一个 AI 搜索产品官网
```

## Brief Score

42/100

这个需求可以生成页面，但如果不补充假设，结果会很不稳定，容易变成泛泛的 AI 产品官网。

## Main Gaps

- 没有说明目标受众。
- 没有说明业务目标和 CTA。
- 缺少产品证明、截图、指标和集成范围。
- 没有品牌语气、视觉方向和设计系统。
- 没有响应式、可访问性和内容边界。

## Recommended Mode

黄金样例使用 quick mode。用清楚可见的假设推进，而不是因为信息不完整停下来。

## Assumptions Used

- 官网面向一个早期但可信的 SaaS 产品。
- 主要受众是知识工作者和小团队。
- 页面目标是推动试用注册，演示预约作为次要动作。
- 没有真实 Logo、截图、客户 Logo、指标或认证徽章。
- 设计要使用可信的产品占位界面，而不是虚构证明。

## Questions For Standard Mode

- 哪些集成已确认可以发布展示？
- 是否有真实产品截图？
- 当前优先目标是试用注册、演示预约，还是候补名单？
- 是否有真实客户证明或安全说明？
- 产品应该更偏企业、创业团队，还是开发者工具气质？

## Strategy Options

### 1. 企业信任型

- Best use case: 团队在评估工作知识和安全性时，需要一个可信的产品官网。
- Visual tone: 克制、产品驱动、字体清晰、中性界面、少量蓝色强调。
- Structure focus: 先讲价值，再展示带来源答案的产品 UI，随后补充工作流、集成范围和安全信息。
- Risk: 如果产品需要更强发布声量，可能显得过于保守。
- Best target tools: huashu-design, Claude Design, v0.
- Status: selected.

### 2. 搜索助手演示型

- Best use case: 页面需要快速演示搜索交互。
- Visual tone: 更互动、更产品前置、略有活力。
- Structure focus: 先展示示例问题和带来源答案，再解释可信度。
- Risk: 可能过度关注演示机制，弱化商业信任。
- Best target tools: huashu-design, v0.

### 3. 创始人发布型

- Best use case: 早期产品需要更锐利地讲清问题。
- Visual tone: 偏编辑感、直接、留白多，文案更强、界面面板更少。
- Structure focus: 先讲知识分散的痛点，再把产品作为聚焦答案推出。
- Risk: 如果证明和安全信息太轻，企业买家会觉得成熟度不足。
- Best target tools: Claude Design, huashu-design.

## Final Choice

选择“企业信任型”。原始需求是“官网”，最稳妥的第一印象是可信、产品驱动、有清楚信任线索的 SaaS 页面。
